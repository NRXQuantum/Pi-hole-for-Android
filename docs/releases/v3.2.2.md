## Pi-hole for Android v3.2.2

This release fixes APK signing: the APK is now built and signed by GitHub Actions with a persistent keystore stored in repository secrets, so future releases install as normal updates instead of failing with **"App not installed"**.

### What changed

- **Stable signing key.** `pideploy.apk` is rebuilt from the pinned upstream 3.2.0 APK and signed with the release keystore. Every CI run verifies the signer certificate (`8E:4A:48:E0:12:27:14:04:39:68:BB:A9:55:2E:BA:59:9D:1D:78:7E:49:F2:1B:EB:6B:33:5E:99:26:2F:B8:EB`) and fails if the wrong key is used.
- **No functional APK changes** compared to v3.2.1: SSH, RDP, web terminal, avahi and Pi-hole v6 fixes are unchanged. Only `versionCode` (316) and `versionName` (3.2.2) differ.
- **Disk images are unchanged** from v3.2.1 and are included again so the `releases/latest/download/...` URLs keep working.

### Assets

| File | Description |

| `pideploy.apk` | Pi Deploy APK 3.2.2, signed with the persistent release key |
| `raspbian32.tgz` | 32-bit ARMv7 Pi-hole image — **default** |
| `raspbian.tgz` | 64-bit ARM64 Pi-hole image |
| `SHA256SUMS` | Checksums for the three files above |

### Upgrading

- **From v3.2.1:** install `pideploy.apk` over the existing app. It is signed with the same certificate, so no uninstall is required and deployments are kept.
- **From upstream 3.2.0 or older:** the signing key is different, so uninstall the old Pi Deploy APK once (export your Pi-hole configuration with **Teleporter** first), then install this APK and create/restore your deployment.

### Checksums (SHA-256)

See `SHA256SUMS` for the exact values of the uploaded files, and `build-info.txt` in the workflow artifacts for the APK's signer fingerprint.
