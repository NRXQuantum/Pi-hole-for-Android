## Pi-hole for Android v3.2.3

This release fixes the runtime failure that prevented deployments with:

```
/system/bin/sh: <stdin>[4]: /data/user/0/com.desktopecho.pideploy/files/bin/pideploy: not found
```

### Root cause

The app extracts its helper binaries and scripts into its private `files/` directory on first start, and records the
version in `files/version`.  It only re-extracts when that marker differs from the version compiled into the app.  A
restored or partially restored data directory can keep the marker while `files/bin/pideploy`, `files/bin/busybox` (or the
`files/bin/sh` symlink created by `busybox --install -s`) is missing.  The app then skips extraction and every deployment
aborts with "not found".  Initialization was also skipped entirely when `WRITE_EXTERNAL_STORAGE` was denied, even though
extraction only needs internal storage.

### What changed

- **Environment integrity check.** Before deciding that the environment is current, the app now verifies that
  `files/bin/pideploy`, `files/bin/busybox`, `files/bin/sh` and `files/cli.sh` exist (binaries must also be executable).
  If anything is missing, the environment is extracted again.
- **No storage-permission dead end.** If the storage permission is denied, the internal environment is still initialized
  (the permission is only needed for external image/log locations).
- **Self-healing before commands.** If a deployment command is about to run while the environment is missing, the app
  rebuilds it first instead of failing with "not found".
- **Version marker matches the APK.** `getVersion()` now reports the release (`3.2.3-317`), so installing an update always
  refreshes the extracted environment once.
- No changes to the disk images or to the Pi-hole configuration.

### Upgrading

- **From v3.2.1 / v3.2.2:** install `pideploy.apk` over the existing app. It uses the same certificate, so no uninstall
  is required and existing deployments are kept. The first start after updating re-extracts the helper environment once.
- **From the upstream 3.2.0 APK or older:** the signing key differs; uninstall the old Pi Deploy APK once (export your
  Pi-hole configuration with **Teleporter** first), then install this APK and create/restore your deployment.
- If a deployment still fails, open the app once, wait for the "Preparing environment" step to finish, then retry.

### Checksums (SHA-256)

See `SHA256SUMS` for the exact values of the uploaded files, and `build-info.txt` in the workflow artifacts for the APK's
signer fingerprint.
