## Pi-hole for Android v3.2.9

This release fixes two UI state problems: the **SSH switch turned itself back on** after leaving and re-entering
Properties, and **START/STOP did not follow the real container state**.

### Why the SSH switch flipped back

`PropertiesActivity` was opened with `restore=true`, so every visit re-imported the profile stored on disk.  That
profile still listed `extra/ssh` in `INCLUDE`, and the import overwrote the saved `is_ssh` preference with `true`.
The switch therefore showed SSH as on even after it had been switched off.  Writing the profile could also fail
silently when a root command had left the config directory owned by root.

### What changed

- **Properties no longer re-imports the profile on open.**  The stored profile is loaded only when the profile
  itself is changed, so the saved preferences stay authoritative.
- **Each preference change is persisted immediately.**  The `include` → `is_ssh` mapping is now symmetric: a profile
  without `extra/ssh` sets the switch to off instead of leaving the previous value in place.
- **`cli.sh` hands the config directory back to the app's owner** before the container starts, so the app can keep
  rewriting `Raspbian.conf` after a root-owned file was created.
- **START/STOP now follows the real container state.**  `cli.sh` records the container's chroot PIDs in
  `files/run/container.pids` after START and removes the file on STOP/unmount.  The main screen polls the file every
  two seconds and confirms each PID still exists in `/proc`, then shows **STOP** while the container is live and
  **START** when it is not.

### Verification

Tested on a Samsung SM-J200G (LineageOS 7.1.2, Android 7.1) with the existing deployment kept in place:

| Test | Result |
| --- | --- |
| Install over v3.2.8 (`adb install -r`) | succeeded, data and container preserved |
| Turn SSH off, leave Properties, open Properties again | switch stays off; `is_ssh=false` and `INCLUDE="bootstrap init"` |
| Container running | **STOP** shown; `files/run/container.pids` contains live PIDs |
| Tap STOP | services stop, marker removed, button changes to **START** within two seconds |
| Tap START | services start, marker recreated, button changes to **STOP** |
| SSH off, tap START | no Dropbear process and no listener on port 2225; Pi-hole DNS (53), web UI (80) and xrdp (3389) start normally |

### Notes

- **Settings take effect on the next START.**  If the container is already running, tap STOP then START after changing
  the SSH switch or port.
- **Same signing key** as v3.2.1–v3.2.8, so this installs as an update.  Existing deployments are kept.
- The disk images are unchanged; only the APK changed.
